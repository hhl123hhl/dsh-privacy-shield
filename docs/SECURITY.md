# SECURITY — dsh-privacy-shield 安全模型与边界

> 本文定义威胁模型、安全边界和已知残留风险。它不是合规承诺；合规映射见 [COMPLIANCE.md](COMPLIANCE.md)。

## 1. 目标资产

- **本地敏感数据**：用户文件内容、对话文本、图片/文件块、工具调用参数中的专有名词与 PII。
- **出境数据**：发往模型服务（DeepSeek 云端 API）的请求内容。

## 2. 设计不变量

1. **本地记录面永不改写**。会话日志、聊天 UI、工具执行只接触原始事件（append-origin）。
   脱敏只发生在"模型可见面"（`Session.deriveEventMessage` 的 derive 补丁副本）与手搓请求兜底中。
2. **占位符确定性**。`<LABEL_8hex>` = HMAC-SHA256(key, `LABEL + "\0" + value`) 前 4 字节
   （`placeholderHash: hmac`，默认；`legacy` = FNV-1a 32 位，可枚举反推，仅建议过渡）。
   掩码是确定性纯函数：跨轮次、fork、冷启动、重放都产出同一占位符，不依赖任何进程内计数器。
   密钥在 `$DSH_HOME/shield/.placeholder.key`；内存降级模式下重启会使占位符变化（有告警）。
3. **还原表（vault）只在内存**。`placeholder → value` 不落盘、不进规则包、不出境、不进审计。
   真值的可重建来源是本地会话日志本身。
4. **审计只记计数与标签**。出境审计、状态输出、报告渲染的硬规则是：任何渲染结果不得包含原始敏感值。

## 3. 威胁模型

### 防护的

| 威胁 | 缓解 |
|---|---|
| 敏感文本（PII、公司/项目/系统名、编号）随模型请求出境 | derive 补丁脱敏（5 类 surface）+ 手搓请求兜底 + 出境明文残留自检 |
| 模型回复中的占位符泄露给最终用户（可用性/正确性问题，非机密性） | 响应流包装还原（含跨 chunk 缓冲） |
| 规则包被误当成还原表转发 | 导入校验拒绝 `vault/values/secrets/plaintext/restore` 字段 |
| 审计文件本身成为敏感数据源 | 审计只写计数与标签，绝不写真值 |
| 词表文件/规则包丢失或损坏导致 profile 起不来 | 启动载入失败降级为警告，不阻断启动 |
| 规则包在传输途中被窃读（词表本身是敏感清单） | `export --encrypt <口令>`：AES-256-GCM + scrypt，文件头 `DSH-SHIELD-ENC/v1`；口令丢失无法找回 |
| 占位符被枚举反推确认敏感值 | hmac 模式：无本地密钥无法重算哈希确认猜测（legacy FNV-1a 无此性质，见 CONFIG.md §5） |
| 临时放行被遗忘 | `/shield pause <分钟>` 内存计时器到期强制恢复，审计行标注 `paused`，status 显示剩余分钟 |

### 不防护的（明确 out of scope）

| 残留风险 | 说明与缓解建议 |
|---|---|
| **本地磁盘与备份** | 本地日志按设计保留明文。磁盘加密、备份管控、访问控制是用户自己的责任 |
| **图片内容** | 不做 OCR/内容识别，图片原样出境。文本类文件块内容会脱敏；二进制与图片放行——UI 与 status 均有明示 |
| **检测启发式的漏报** | 规则+词表驱动，无 NER 模型。漏报的敏感值会以明文出境——用 `terms` 补自己的专有名词，并用出境审计的明文残留计数做持续观察 |
| **占位符标签变化** | 配置变化使同一值换标签 → 新占位符，旧引用依赖 vault 命中才能还原 |
| **vault 逐出** | 超过 `maxVaultEntries` 后最旧映射被静默丢弃，对应占位符不再还原 |
| **热卸载/替换插件** | 0.2.1 起基于 derive 补丁：卸载或替换插件仅使派生恢复原样（明文出境），不会让会话拒绝派生；安装/升级/卸载仍需重启 profile 使代码改动生效 |
| **恶意模型输出** | 插件不校验模型回复内容本身；还原只替换已知占位符 |
| **内存中的明文** | vault 与请求缓冲在进程内存里；本机恶意软件可读取 |

## 4. 审计能力

- 每次出境请求统计占位符数量与标签分布（`stats.outbound*`）。
- `audit.verifyOutbound`（默认 `full`）用同一套检测器复核出境文本，发现明文残留计入 `violations` 并记录标签与时间（不记明文）。
- `audit.jsonl`（默认 `true`）把每次审计追加为 JSONL 一行（可用 `audit.jsonlPath` 指定位置，相对路径落在 `$DSH_HOME/shield/` 下）；`audit.retentionDays`（默认 30）自动清理超期行。
- 浏览器半边（Web UI）取数走 DSH 通用 RPC 通道（自带 Host/Origin 与浏览器鉴权）；测试台文本只在本地往返，不增加新的出境面。
- `/shield status` / `/shield vault` / `/shield terms` 只输出计数与标签。

## 5. 运行建议

- 先用 `mode: observe` 观察一段时间，看 `/shield status` 的命中分布，再把 `terms` 调全，最后切 `enforce`。
- 不要把 `onUnmaskable: block` 当作常态——它会在冻结请求检出明文时直接抛错阻断该次请求，适合严格环境。
- 规则包按词表的密级保管：它不含还原表，但词表本身就是敏感词清单。需要经低信任通道传输时用 `--encrypt`。
- 密钥文件 `.placeholder.key` 按口令级资产保管：拿到它就能反推所有历史占位符对应的真值类别。
