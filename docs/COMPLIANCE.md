## 2. 本插件的时间线：数据到底流经哪里

合规讨论必须先说清数据流。`dsh-privacy-shield` 介入的位置如下：

```
             ┌──────────────── 本地（你的机器）────────────────┐   ┌── 云端 ──┐
             │                                                 │   │          │
你输入 ──────┼──► append-origin 原始事件 ──► 本地会话日志（明文）│   │          │
             │            │                                    │   │          │
             │            └──► 聊天界面渲染（明文）             │   │          │
             │                                                 │   │          │
             │    Session.deriveMessages()                     │   │          │
             │            │                                    │   │          │
             │            ▼                                    │   │          │
             │    【本插件 derive 补丁】脱敏副本                    │   │          │
             │            │                                    │   │          │
             │            └────────────────────────────────────┼──►│  模型     │
             │                                                 │   │          │
             │    模型响应流 ◄─────────────────────────────────┼───│          │
             │            │                                    │   │          │
             │    【本插件 llm/stream 还原】占位符 → 真值        │   │          │
             │            │                                    │   │          │
             │            └──► assistant 消息以真值落盘并展示   │   │          │
             └─────────────────────────────────────────────────┘   └──────────┘
```

三个关键事实：

1. **出境的是被改写的副本。** 送模型的请求由 derive 补丁在派生阶段产出，命中的敏感文本已被替换为
   `<LABEL_8位hex>` 形式的占位符。改写**不落盘**——它只存在于送给模型的那一份消息里。
2. **本地保留明文是刻意选择。** 本地会话日志与聊天界面显示真实值，这正是"用户能看到真实结果"
   的前提。**本地磁盘不因此受到保护。**
3. **还原发生在本地、展示之前。** 模型响应流被包装，占位符在落盘与展示前被还原为真值。

## 3. 原则 → 功能映射

以下逐项给出"原则 → 本插件提供的手段 → 代码依据 → 边界"。**每一行都只是"有助于"，不是"满足"。**

### 3.1 最小必要 / 目的限定

| 项 | 内容 |
|---|---|
| 原则 | 只处理实现处理目的所必需的个人信息范围；不超范围收集与使用。 |
| 本插件提供的手段 | 按实体类型逐类启用/关闭检测；`entities` 允许把处理范围收窄到确有需要的类型；`ipv4`/`ipv6` 默认关闭以避免不必要的处理；`surfaces` 允许逐面收窄覆盖范围；`/shield off` 可临时整体停用。 |
| 代码依据 | `lib/config.js:53-54`（`entities` 过滤为 22 个已知实体名）、`lib/config.js:55-60`（`surfaces` 逐面开关）、`lib/constants.js:42-66`（20 个默认实体 + `OPT_IN_ENTITIES = ['ipv4','ipv6']`）、`lib/runtime.js:120-127`（`active` 全局开关）。 |
| 边界 | 本插件**只减少出境内容**，不减少本地留存的个人信息，也不判断"某项处理是否有必要"。是否必要由使用者决定。`entities` 的默认值并非最小集合，需要使用者自行收窄。 |

### 3.2 去标识化 / 降低可识别性

| 项 | 内容 |
|---|---|
| 原则 | 通过对个人信息的技术处理，使其在不借助额外信息的情况下无法识别特定自然人。 |
| 本插件提供的手段 | 出境前把命中的敏感文本替换为确定性占位符 `<LABEL_8位hex>`；还原映射表仅驻内存、不落盘；审计与命令输出只回显计数与标签，不回显真值。 |
| 代码依据 | `lib/engine.js`（`makePlaceholder` / `hash8`）、`lib/crypto.js`（HMAC-SHA256 占位符与密钥管理）、`lib/runtime.js`（`maskBlock` 只改写 `text`/`reasoning` 的文本、`tool-call` 的 `arguments` 与文本类 file 块）、`lib/vault.js`（`record` 仅写内存 Map）、`lib/report.js`（渲染层硬规则：不得包含原文）。 |
| 边界 | **这是"假名化/去标识化"，不是"匿名化"。** 占位符是 `(标签, 真值)` 的确定性函数，是一种**可逆**的替换：任何持有还原表或能重跑检测器的人都可以还原。因此出境数据仍应被视为**个人信息**，不满足"无法识别且不能复原"的匿名化标准。v0.3.0 默认 `placeholderHash: hmac`：占位符后缀是 HMAC-SHA256 前 4 字节，**无密钥者无法重算确认猜测**；`legacy`（FNV-1a，非密码学哈希）仍可被枚举反推，仅建议过渡。 |
| 影响 | 若你的合规分析依赖"已匿名化"这一结论，本插件**不能**支持该结论。 |

### 3.3 本地处理 / 数据不出境

| 项 | 内容 |
|---|---|
| 原则 | 减少个人信息向境外或向第三方的传输；传输前评估风险并采取必要措施。 |
| 本插件提供的手段 | 在本地完成检测、替换、还原；还原表只驻内存；审计只在出境请求上统计计数。 |
| 代码依据 | `lib/derive-patch.js`（derive 补丁在本地派生阶段替换）、`lib/stream.js:63-94`（响应流在本地还原后再落盘）、`lib/runtime.js:202-248`（`auditOutbound` 只统计占位符与标签，`stats.lastViolation` 只存标签名与计数）、`lib/vault.js:17-80`（还原表无任何序列化路径）。 |
| 边界 | **本插件不能阻止你在对话里直接提供未命中的个人信息。** 它降低出境量，但不改变"云端服务商仍会收到被送出内容"这一事实。跨境传输的合法性基础（如标准合同、认证、安全评估、单独同意等）**不在本插件能力范围内**，需由使用者另行安排。 |

### 3.4 可审计 / 可验证

| 项 | 内容 |
|---|---|
| 原则 | 对个人信息处理活动进行记录，具备可追溯、可核查的能力。 |
| 本插件提供的手段 | 出境请求逐个计数占位符数量与标签分布；在 `enforce` 模式下对出境文本**重跑检测器**，把仍然命中的位置计为"明文残留";`/shield status`、`/shield verify` 展示审计结论；`/shield audit [天数]` 按天聚合、`audit export` 导出 CSV（v0.3.0）；`onUnmaskable: 'block'` 可在冻结请求仍含明文时**拒绝发送**。 |
| 代码依据 | `lib/runtime.js:202-248`（`auditOutbound`：统计 `outboundRequests`、`outboundPlaceholders`、`outboundByLabel`，并在 `verifyOutbound !== 'off'` 且文本不超长时重跑 `detect`）、`lib/runtime.js:229-243`（残留记录 `{at, sessionId, labels[最多20], count, handBuilt}`）、`lib/stream.js:145-150`（`onUnmaskable === 'block'` 时抛错阻断）、`lib/report.js:73-102`（`formatVerify`）。 |
| 边界 | `audit.jsonl: true` 可把每次出境审计追加为 JSONL 一行（`lib/rules.js: appendJsonLine`），但**每行只有计数与标签**（占位符数量、标签分布、违规计数、会话 id、时间戳），不含被处理文本本身。它不是完整的合规审计留痕系统——不提供处理目的、法律依据、数据主体等合规审计要素；运行时统计（`/shield status`）在 profile 重启后清零，JSONL 文件则持久保留。 |
| 边界 | 残留检测本身是启发式的：它只能发现"被检测器命中却没被替换"的明文，**发现不了检测器的漏检**（未命中的值不会计入残留）。 |

### 3.5 安全措施 / 防泄漏

| 项 | 内容 |
|---|---|
| 原则 | 采取技术措施防止个人信息泄露、篡改、丢失。 |
| 本插件提供的手段 | 出境内容被替换为占位符；还原表不落盘；渲染层不输出原文；冻结请求漏检可阻断。 |
| 代码依据 | 同上 §3.2、§3.4 各项。 |
| 边界 | **本插件不加密本地数据，也不保护本地磁盘。** 本地会话日志按设计保留明文。静态加密、备份加密、文件权限、终端防护、屏幕共享风险**均需使用者自行解决**。详见 [SECURITY.md](SECURITY.md)。 |

### 3.6 告知同意

| 项 | 内容 |
|---|---|
| 原则 | 处理个人信息应取得同意，并履行告知义务。 |
| 本插件提供的手段 | **无。** 本插件不涉及与数据主体的交互，不生成告知文本，不管理同意。 |
| 边界 | 这是**组织与流程层面**的义务，技术插件无法替代。若你把脱敏后的数据发给第三方，仍需自行履行告知同意与合同安排。 |

### 3.7 数据分类分级 / 影响评估

| 项 | 内容 |
|---|---|
| 原则 | 对数据进行分类分级，对高风险处理活动开展风险评估。 |
| 本插件提供的手段 | 按 28 类实体标签对命中内容分类计数（`stats.byLabel`、`outboundByLabel`），实体带 high/medium/low 敏感度分级（`minLevel` 可过滤默认集合），可作为分类分级的**输入参考**。 |
| 代码依据 | `lib/constants.js`（`ENTITY_LABELS` 28 类 + `ENTITY_SENSITIVITY` 分级）、`lib/runtime.js`（`addHits` 按标签累计）。 |
| 边界 | **计数不等于分级结论，也不等于影响评估。** 本插件不评估风险等级，不生成评估报告，不识别"敏感个人信息"这一法律类别（例如它无法区分一般个人信息与敏感个人信息，也无法识别生物识别、医疗健康、金融账户等特定类别）。 |

### 3.8 与 GB/T 41391 的关系

| 项 | 内容 |
|---|---|
| 原则 | App 收集个人信息的最小必要与告知同意要求。 |
| 本插件提供的手段 | `entities` / `surfaces` 提供了**收窄处理范围**的技术手段，与"最小必要"的思路方向一致。 |
| 边界 | **适用对象不同。** GB/T 41391 规范的是移动 App 运营者面向用户的收集行为。`dsh-privacy-shield` 是本地桌面工具插件，不面向数据主体收集信息。因此本插件与该标准**不存在直接的符合性关系**，此处仅作原则层面的方向呼应，不应被理解为对标准任何条款的满足。 |

## 4. 明确不属于本插件能力范围的事项

以下事项**本插件不做、不保证、也不声称**。列出来是为了避免误用：

1. **不作匿名化保证。** 占位符可逆，出境数据仍属个人信息（见 §3.2）。
2. **不作 100% 召回保证。** 检测是规则与词表驱动的启发式方法，**没有机器学习 NER 模型**
   （`lib/patterns.js`、`lib/detectors-cn.js`）。非典型机构名、无引导词的项目名、不带称谓的人名
   等**会漏检**。漏检的值会以**明文**出境。
3. **不做 OCR、不做图片内容识别。** 图片与文件块原样放行
   （`lib/runtime.js:168-169`）。`mediaPolicy: 'strip'` **未实现**——设为 `strip` 只改变
   `/shield status` 的显示，不产生任何剥离行为（`lib/runtime.js:150-170`）。
4. **不提供合规审计要素。** `audit.jsonl` 落盘的只有计数与标签（见 §3.4），不含处理目的、
   法律依据、数据主体等要素，不能替代合规审计系统。
5. **规则包本身可能敏感。** `/shield export` 导出的规则包（`dsh-shield.rules/v1`）只含词表与
   实体开关、绝不含还原表（导入校验拒绝 `vault/values/secrets` 类字段），但词表本身就是
   敏感专有名词清单，导出与分享需按同等密级保管。
6. **模型工具的边界。** `shield_scan` 只回占位符化文本与计数（`lib/tool.js`），即使模型主动
   要求也拿不到真值；但模型仍能看到它自己上下文里的占位符文本。
7. **不保护本地存储。** 本地明文留存 + 不加密。
8. **不代替任何法律程序。** 不生成隐私政策、不生成同意书、不生成评估报告、不做跨境合规判定。
9. **不保证运行时不出现故障。** 详见 [SECURITY.md](SECURITY.md) 的威胁模型与已知限制。

## 5. 使用者的责任清单

若你打算在企业环境中部署本插件，以下事项**需要你自行完成**：

**配置层面**

- [ ] 把 `mode` 从默认的 `observe` 改为 `enforce`（默认值**不改写任何内容**）。
- [ ] 按最小必要原则收窄 `entities`（并确认 `ipv4`/`ipv6` 是否确实需要开启）。
- [ ] 按最小必要原则收窄 `surfaces`。
- [ ] 用 `terms` 补齐本组织特有的机构名、项目名、系统名、编号——**这是最主要的漏检补救手段**。
- [ ] 评估是否启用 `onUnmaskable: 'block'`（拒绝发送仍含明文的冻结请求）。
- [ ] 了解 `audit.verifyOutbound` 保持非 `'off'` 才能让残留自检生效。

**运维层面**

- [ ] **安装/升级/卸载本插件或改动其配置后，必须重启 DSH profile 才能生效。**
      （0.2.1 起基于 derive 补丁：热卸载/替换只会使派生恢复明文，不会损坏会话日志或导致会话拒绝派生，
      但新代码与配置不会在运行中的 profile 里自动加载。）
- [ ] 建立本地会话日志的磁盘加密、访问控制与备份策略（本插件不提供）。
- [ ] 明确谁可以读取本机的会话日志与还原表所在进程。
- [ ] 决定审计计数的留存与复核方式（本插件不落盘，需自行截取 `/shield status` 输出）。

**评估层面**

- [ ] 自行评估漏检造成的残余风险，并据此决定是否可以在特定场景使用。
- [ ] 自行判断出境内容的合法性基础与跨境安排。
- [ ] 自行判断是否需要开展个人信息保护影响评估。
- [ ] **就本文的任何映射结论，咨询你的法务或合规人员。**

## 6. 小结

`dsh-privacy-shield` 能做的一件事，说清楚就是：**让送往模型的文本只含占位符，并把占位符在本地还原成真值。**

它的技术手段对应到合规语言，是"有助于满足最小必要、去标识化、本地处理、运行时自检等一般性原则"。

它不是认证、不是匿名化工具、不是审计留痕系统、不是法律意见，也不保护你的本地磁盘。

**合规责任由使用者承担。**
