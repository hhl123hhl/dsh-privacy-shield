# dsh-privacy-shield v1.2.0 · 发布说明

**主题：让"没被引导词带出来"的专名也能被提出来。**

## 这一版解决什么

1.1.0 让"表格里的裸值"也能被遮，但**候选召回**仍然只有三路：引导词（"项目名称："）、词典后缀（…公司/…项目）、高频片段。
于是在真实材料里，`智慧园区`、`星联智造`、`蓝鸟计划` 这类**没有引导词、也不在词典后缀里**的专名——既不遮，也**不会出现在候选里**。用户看不到它，就永远补不进词表。

1.2.0 把候选召回做成多路，并给每条候选附上"凭什么推荐它"。

## 多路召回（`lib/name-candidates.js`）

| 路径 | 证据 | 典型命中 |
| --- | --- | --- |
| 列语义 | 列头「项目名称」「客户名称」「实施单位」 | 表里裸写的项目名、机构名、人名 |
| 上下文同现 | 与 合同/客户/甲方/验收/交付/中标/里程碑… 同句 | 散文里顺带提到的专名 |
| 后缀扩展 | 宽后缀（项目/工程/计划/课题/系统/平台/数据库/中台/门户/局/委/办…）+ 期次（一期/二期/试点/改造/升级/迁移） | `智慧园区平台二期`、`XX 局` |
| 引号包裹 | 《…》/「…」/“…” | 文档标题、需求名 |
| 高频片段 | 同文档/同会话重复 ≥2 次 | 反复出现的内部代号 |

- `/shield scan-doc <文件>` 与 `/shield learn` 共用这套召回。
- `/shield terms adopt` 前会显示证据，例如：`智慧园区　count 2　建议 PROJ　证据：列头「项目名称」；同句出现「验收」`。
- 候选**不会自动生效**，必须人工确认后入词表——召回是启发式，误遮一个常用词比漏遮一个项目名更伤可用性。

## 计数语义修正

同一个值常被多路同时召回（如"后缀 + 高频"）。旧实现把各路计数相加，会把"出现 2 次"报成"出现 4 次"。现改为**取单路最大值**（`Collector` 与 `mergeCandidateInto` 同步），让 count 更接近真实出现次数。

## 两列表也能按列处理

表格分隔符判定从"≥2 个制表符"放宽到"≥1 个"：`姓名\t金额`、`单位\t联系人` 这类两列 TSV 现在同样走列语义。

## 碎片过滤

只有后缀外壳的值（`有限公司`、`分公司`、`项目部`、`研究院`）不再进候选。它们在真实材料里常靠"出现 N 次"混进候选，确认后只会得到一条永远匹配不到专名的噪声规则。判定方式：从尾部反复剥除通用后缀，剥完不足 2 字即丢弃。

## 兼容性

- 规则包 schema（`dsh-shield.rules/v1`）、加密包文件头（`DSH-SHIELD-ENC/v1`）、数据目录（`$DSH_HOME/shield/`）、cordis 插件 id（`shield`）、`/shield` 命令集全部不变。
- 候选池仍是 30 分钟 TTL，超时自动清空。

## 验证

- 单测 **331/331 通过**（新增 `test/name-candidates.test.mjs` 10 项）。
- 样例业务表格（百余行 × 十余列）抽成 TSV 后：期次后缀召回项目名、同句召回机构名、`机房升级` 按项目召回，噪声可控。
- repo / `release/` / 已装副本三方 SHA256 一致。

## 已知边界

- 召回是规则启发式，不做语义理解：跨句指代、简称与全称的归并仍靠人工。
- 图片/扫描件表格不处理（沿用 `mediaPolicy: pass`）。
- 升级后需**重启 DSH** 才加载新版本（插件在启动时装配）。
